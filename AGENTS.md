# GPFF: working notes for Claude

GPFF is a generative pseudo-force field. Molecules are generated by a time-agnostic PaiNN (schnetpack) force field trained on the pseudo-energy |x̃−x0|², with VE noise and direct denoising. The paper is arXiv 2605.19050 (Stefaan Hessmann; upstream stefaanhessmann/gpff). The user extends it for their MSc. Main dataset: QM9. Also CrossDocked2020 ligands and GEOM-Drugs.

## Standard workflow
1. Edit and commit in a local worktree (commit only if asked; otherwise snapshot the working tree).
2. Snapshot it to hydra: `git archive <sha> | ssh hydra 'd=~/gpff/frozen_code/<sha>-<topic>; mkdir -p $d && tar -x -C $d && chmod -R a-w $d'`.
3. Train: `cd ~/gpff && [DATA_FAMILY=.. DATASET=.. SIF=..] APPTAINERENV_PYTHONPATH=$GPFF/frozen_code/<snap>/src sbatch [--constraint=40gb] slurm/train.sbatch <overrides>`.
   Defaults: experiment=gpff, seed 999, 10000 epochs, batch 512. Fast opt-ins: `data.load_properties=[] data.cache_in_memory=true data.persistent_workers=true callbacks.deterministic_data_seed.per_sample_train_noise=true compile={dynamic:true}` (compile needs the gcc SIF). Add `+callbacks=milestones` for milestone checkpoints.
4. Resume: gpu-2d has a 48 h limit and no auto-requeue. Resume with `run.ckpt_path=<run>/milestones/epoch_N.ckpt` (PL 2.6.6 rewrites `last.ckpt` only on improvement), using the same SIF, snapshot, DATASET and overrides.
5. Evaluate milestones with the study's `submit_milestone.sh`, `poll.sh` and `compare.py` (paired McNemar against a control). Compare models paired, on the same split and noise.

## Verified pitfalls
- **Two QM9 DBs.** The paper DB has 123,569 rows (`data/qm9/current`). The old DB has 121,651 rows and is the paper DB minus every fluorine molecule. A split is valid only with its own DB. Old-DB models never trained the F embedding and output forces up to 1e26 on CF3 molecules.
- `/dev/shm` is shared between jobs on a node. Billing is max(0.25/core, 0.05/GB, 5/GPU), and 40gb nodes have 16 cores per GPU.
