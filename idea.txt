━━ CLAUDE 11:56:13 ━━
Compile fails because of the extra derivative the conservative model takes inside its own forward pass.

**Where the second derivative comes from.** In `cons-det` the force isn't a network output. schnetpack's `Forces` module computes it inside the forward pass:

```python
F = -torch.autograd.grad(E, R, create_graph=self.training, retain_graph=self.training)
```

In training, `create_graph=True` is required. The loss is on F = −∂E/∂R, so `loss.backward()` must differentiate through that gradient a second time to reach the weights. That is a double backward: the backward of the energy graph runs inside the forward, and is then itself differentiated.

**What compile does with that.** `torch.compile` traces the model up to the `autograd.grad` call. AOTAutograd then builds a fused forward graph and a matching backward graph for the energy computation. It builds that backward on the assumption that it runs once, at the end of the step, and is never differentiated. On that assumption it "donates" buffers: the saved activations' memory is reused or freed in place during the backward. A backward run with `create_graph=True` would need those tensors kept alive and the backward itself recorded for a second pass. So the compiled backward refuses, which is the smoke job's error (5130014):

```
RuntimeError: This backward function was compiled with non-empty donated buffers which requires
create_graph=False and retain_graph=False. ... or set torch._functorch.config.donated_buffer=False to disable
```

It fails at the first `autograd.grad` in the first forward pass, before the loss is even computed. The direct-force models never take this path: their only backward is the final `loss.backward()`, so compile is fine there.

**Would `donated_buffer=False` fix it?** It removes this particular check. I haven't tested it, but I expect the next obstacle: AOTAutograd's compiled backward has historically not been differentiable, so a double backward through it raised its own error. Whether the container's torch 2.14 supports that now is something only a run will tell. A test is a ~10-minute gpu-2h job: the same smoke step with that flag set. It would need a one-line code change, since nothing in the config exposes it.

**What it costs.** Without compile, `cons-det` runs at ~2.9 it/s against the control's ~13 it/s. Part of the gap is compile and part is the double backward itself, which no compiler setting removes. If speed matters more than a fully conservative run from scratch, the usual alternative is to pretrain with a direct force head (compiled) and fine-tune with the conservative head for the last part (Bigi et al., ICML 2025, the paper the branch cites). That needs the run to start from another model's weights, which the `cba1ce2+…init-model` snapshot added on another branch.
